Adapting the profile ​

Four private files adapt the harness to one user and one machine. None of them is in the repository. They are in ~/.config/research-harness/, and examples/ holds an example of each, with a comment on every key that says what its value is.

Copy each example that you need and write your values into the copy, as the step The profile and the model tables of setup-macos.md and setup-linux.md shows. A template of the repository names a profile key as {key}, and a subcommand renders the template with the profile before it uses it. A template that names a key that the profile does not have stops the subcommand, and the message names the key.

Read a value ​

harness get prints the value of one key, one line for each item of a list. harness render prints a template rendered with the profile. Run these commands in the checkout:

bash
harness get repository_roots
harness render launchagents/kaimon.plist

Both subcommands read every key that they name.

The home directory and ~ ​

The key home is optional. Without it, home is the home directory of the user who runs harness. A given home must be an absolute path without ~; otherwise the subcommand stops, and the message names the key. A trailing slash is removed.

A string value that is ~, or that starts with ~/, means home: ~ becomes home, and ~/Research becomes home followed by /Research. The same holds for each such item of a list. Any other ~ stays as written, a~b and ~name/x too. So examples/profile.toml works as copied, on every machine.

One profile for every machine ​

The template host is the machine whose Claude Code memory is the template for the other machines. The key autocommit_branch names the branch of the origin of ~/.claude that claude-autocommit pushes to: main on the template host, and a branch of its own on each other machine. The optional key template_host names the template host by its short host name: the host name up to its first ., as hostname -s prints it. Without autocommit_branch in the profile, its value is:

  • main when the profile has no template_host;
  • main on the machine whose short host name is template_host;
  • memory/<short host name> on every other machine.

The comparison is exact, so Alpha and alpha are two machines, and an empty host name gives main. A given autocommit_branch is the branch on every machine. A template_host that is empty, holds a . or is not a string stops the subcommand, and the message names the key. Every subcommand reads the same value, and harness get autocommit_branch prints it. So with template_host and no autocommit_branch, one profile works unedited on every machine of one user: write it once, keep it in a private place, and copy it to each machine.

The keys of the profile ​

The table names each key of examples/profile.toml and the subcommands that read it, in addition to harness get and harness render. The keys memory_project and tree_agents, each a string, and org, repository_roots and leak, each a list of one string or more, are required. Every other key is optional, and the table gives its value without the key.

Every subcommand that reads the profile checks it first. An unknown key, a table such as [setup] among them, a missing required key, a value of the wrong type and an empty required list stop the subcommand with exit status 2. The message names the file, the key and, except for an unknown key, the type that the key takes. The retired keys extra_domain, opencode_providers and omp_providers stop it too, and the message names the file that replaces each. doctor reports each of these as a FAIL of its profile check, which quotes the message.

The tables of the model tables ​

An agent or a skill names a tier in its model:: large, medium or small. Only harness install reads the model tables. It maps each tier to the model of each frontend.

OpenCode and oh-my-pi share every table but [claude] and [antigravity], Antigravity's table of the tiers, so that their agents run on the same models.

A table that names a tier by an old name, opus, sonnet or haiku, stops harness install with exit status 2, an error, and the message names the rename. install then checks the whole file before it plans any frontend: a table that no frontend reads, a key that a table does not name, a [claude] without one of the three tiers and a value of the wrong type stop it with exit status 2, and the message names the file, the table and the key. Each table is optional, and a missing one is empty; a frontend that needs it stops install then, as [claude] does, and [antigravity] once ~/.gemini/ exists. architecture.md shows how each frontend reads a tier.

The network overlay ​

The settings template names no host. settings/network.toml holds the hosts of the harness, and the overlay network.toml beside the profile adds your own, such as the library resolver of your institution. The overlay is optional. examples/network.toml shows it. Both files have the same keys, and each key is optional in the overlay.

keywhat it holdswhat the install writes
allowthe hosts that the WebFetch tool and a sandboxed command can reach; write a host, never *.XWebFetch(domain:X) in permissions.allow; X in sandbox.network.allowedDomains, and *.X too when X is its own registrable domain
infrastructurethe hosts that only a sandboxed command can reach, such as a package registry; *.X is allowedX in allowedDomains, as written
denythe hosts that neither can reach; *, *.X and X:port are allowedX in sandbox.network.deniedDomains; WebFetch(domain:X) in permissions.deny, except for an entry with a port
[deny_reasons]a reason for a deny entry, keyed by the exact entrysandbox.network.deniedDomainReasons, which Claude Code shows the model when the sandbox refuses the host

install, render of the settings template and settings read both files. A deny entry of either file removes each allow and infrastructure host that it matches from the generated allow lists. A deny entry with a port leaves the host on the allow lists. The sandbox refuses a host that no list names, with no prompt, because the template sets strictAllowlist. A WebFetch of such a host is on no list either, so it asks in the default permission mode.

These cases stop the subcommand with exit status 2:

  • an entry that is a URL;
  • an entry with a port outside deny;
  • a host in both allow and deny of one file;
  • a key that the table does not name.

The profile key extra_domain stops every subcommand that reads the profile: move its hosts into the overlay's allow.

The lists apply to Claude Code only. OpenCode and oh-my-pi have no network allowlist.
