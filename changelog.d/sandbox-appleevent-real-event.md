- **The probe `appleevent` of `sandbox/probe-daemon.jl` sends a real Apple Event, and K142 leaves `KNOWN_ISSUES.md` as a false result.** The probe ran `osascript -e 'tell app "Finder" to get name'`, which AppleScript answers from the script itself without an event, so it gave `:allowed` under any profile. It now asks the Finder for `name of startup disk`, which only an event answers. On macOS 27.2, under the rendered Kaimon profile and outside every agent sandbox, that event fails with `-54`, and an `AESendMessage` call that does not go through `osascript` fails with `-600`; the profile's `(deny appleevent-send)` and its deny of two Mach services each stop the event alone, before the Automation consent of macOS. So the Kaimon job cannot send an Apple Event to another app: `OPEN_GAPS` is empty, the header of the probe file expects `:ProcessFailedException` of `appleevent`, the cases of `harness test jobsandbox` pin both and the new default command, and `sandbox/daemon.toml` and the docs say that the profile stops an Apple Event.
