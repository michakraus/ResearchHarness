- **The Kaimon server starts under its Seatbelt profile again.** The juliaup launcher, which starts the server and every Julia of its sessions, opens `~/.julia/juliaup/.juliaup-lock` for writing at every start, and the profile denied every write below `~/.julia/juliaup`, so the launcher exited with "Could not create lockfile: Operation not permitted" and launchd restarted the server without end. A new key of `sandbox/daemon.toml`, `allow_write_files`, names single files that a job writes inside a write deny; the profile allows them after the write denies. Kaimon's only such file is the lock file, so `juliaup.json` and the installed Julia versions stay unwritable, and the profile of `julia-update` does not change. `harness test jobsandbox` also starts the launcher under Kaimon's profile when `~/.juliaup/bin/julia` exists. Run `harness setup` with the component `jobs` to render the profiles again and reload both jobs.
