- **git, gh and glab use one fine-grained forge token per owner, from a token store that `harness install` routes.** The store `~/.config/research-harness/forge/<host>/<name>.store` holds one token per GitHub owner, `default.store` for every other owner, and one GitLab group token, each as a `credential-store` line, mode 600. Where the store exists, `harness install` renders `~/.config/research-harness/forge.gitconfig`, mode 600, with git's owner-scoped credential sections and a get-only helper, so a `git credential reject` never erases a token, and a reset for `gist.github.com`; it exits 2 on a store or host directory that it cannot list, a store file that is no regular file or that the group or others can read, a file name that is no owner's name, a host directory name that is no host name in lower case, or a line that is not the one line of its host, and prints a notice while `~/.gitconfig` does not include the file. The new `~/.local/bin/gh`, installed with the launcher from `scripts/gh-token.py`, runs gh with the token of the owner that the command's own argument, `-R`, `GH_REPO` or `origin` names, and with no token and an empty `GH_CONFIG_DIR` for a host other than `github.com` or where no store file serves; it refuses a command, and runs nothing, where an argument that gh may read as `-R`, but that the wrapper cannot read as `-R` with certainty, names another owner or host. `agentbox` exports `GIT_TERMINAL_PROMPT=0`, fresh empty `GLAB_CONFIG_DIR` and `GH_CONFIG_DIR` directories, and `GITLAB_HOST` and `GITLAB_TOKEN` from the store's one GitLab file. The settings template denies the store to Claude Code's sandbox and to the frontends' read tools, and every frontend's `own` lets its srt file read it. The tokens themselves, and the removal of the broad logins, are steps of the user that `docs/src/components/sandbox.md` lists.
