Challenges ​

A coding agent writes code fast, and most of that code is right. The rest is the problem: a test that passes with the feature deleted, an edge case that nobody decided, a report that says "done" for work that is half done. A human reviewer catches some of this, but a reviewer who reads every line of every change is the bottleneck that the agent was to remove. This page names the failure modes of agentic coding and the answer of the harness to each. The other pages of this section describe the answers one by one.

From a task to a merge ​

From a task to a merge. A task becomes a spec. A builder writes the tests and the code, and the gates run on its branch. Blind critics judge the branch against the spec: two in round 1, then one in each verify round. A FAIL goes back to a new builder; a PASS opens a pull request, and you merge it. A defect outside every clause of the spec, in a class that the edge catalogue does not hold, becomes a new line of the catalogue, and the next spec decides that edge in advance.

Three ideas carry the whole pipeline:

  1. Write the benchmark before the code. The spec and its named mutants exist before the builder starts. So the critic judges against a fixed text, and the builder cannot move the goal.
  2. Separate the contexts. The builder, the critic, the advisor and the arbitrator each work in a context of their own. No judgement comes from a context that has a stake in the result.
  3. Turn what you learn into a check. A defect class that a critic finds becomes a line of the edge catalogue, and a mechanical rule becomes a static check. The next part starts with more decided, and the loop gets shorter.

What stays with you ​

The harness moves review out of your hands where a command or a fresh context does it as well. Some decisions stay yours:

  • The goal and the plan. You agree on the task and its done condition, and you decide the questions of the decision parts (Tasks).
  • An irreversible decision inside the loop. The advisor decides a question that can change inside the pull request; a public interface, for example, goes to you.
  • The merge. No agent merges a pull request that its own session opened (Review and pull requests).

The cost ​

Each new context costs tokens, and two critics in round 1 cost twice what one costs. The harness spends this where a defect is expensive: a part that draws a security boundary, predicts what another tool reads, or has a slow gate gets the full loop. A small part with a fast gate gets the small loop, and a mechanical change gets no critic at all. The builder-critic loop gives the four tiers.

Example: a feature in a Julia package follows one task through the whole pipeline.
