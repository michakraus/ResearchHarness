The srt settings of the CLI frontends ​

srt, the sandbox runtime, runs one process and everything that it starts inside one sandbox. It reads one settings file. harness install writes one such file for each CLI frontend that the profile's [setup] chooses:

text
~/.config/research-harness/sandbox/claude.json
~/.config/research-harness/sandbox/opencode.json
~/.config/research-harness/sandbox/omp.json
~/.config/research-harness/sandbox/antigravity.json

The launcher agentbox starts a frontend under srt with its file, as the launcher describes. A frontend that starts without it does not read the file.

The files come from two sources. The sandbox section of the Claude Code settings template, settings/settings.proposal.json, stays the source of the lists that every frontend shares: the write paths, the write and read denies, the credential files and the network rules, with the domains that settings/network.toml and the profile's overlay give. The policy file sandbox/policy.toml holds only what srt adds to them. lib/harness/sandbox.py renders the files from both.

The policy file ​

sandbox/policy.toml has a table [read] and a table [frontend.<name>] for each of claude, opencode, omp and antigravity. Every path starts with ~/.

keywhat it holds
read.allowthe paths that every frontend reads under the read limit
frontend.<name>.statethe frontend's own directories and files, which it reads and writes
frontend.<name>.deny_writewrite denies that the frontend adds to the template's
frontend.<name>.ownthe template's deny entries that the frontend reads and writes itself

The read limit denies reads of the whole home directory and allows the paths of read.allow again. A path that the template denies stays hidden inside an allowed path: in srt a deny inside an allowed path wins. Claude Code's own is ~/.claude.json, which Claude Code writes itself; a write deny of it would stop the whole process under srt. The cost is that a command that Claude Code runs can also write the file, because the sandbox of the whole process cannot tell the frontend from its own shell. oh-my-pi adds the write denies ~/.omp/agent/config.yml and ~/.omp/agent/extensions.

harness install exits with status 2 on a policy file with an unknown key, a missing key or frontend, a value that is not a list of strings, a path that does not start with ~/, or a path with a .. segment, which could leave the home directory. The message names the key or the path.

The rendering rules ​

srt_settings gives one frontend's object, with the keys network and filesystem and no other:

keyvalue
network.allowedDomainsthe template's, in order
network.deniedDomainsthe template's, or [] where it has none; srt refuses a file without the key
network.allowLocalBindingthe template's
filesystem.allowWritethe template's, without each entry at or below another frontend's state path; then the frontend's state; then the real path of $TMPDIR, where it is set and not empty
filesystem.denyWritethe template's, without the frontend's own; then its deny_write
filesystem.denyReadthe home directory; then the template's; then each path of credentials.files; without the frontend's own
filesystem.allowReadread.allow; then the frontend's state

Each ~ and ~/ prefix becomes the home directory, so the files hold absolute paths. A list holds no entry twice, and the first occurrence keeps its place. "At or below" compares whole path components: ~/.claude.json is not below ~/.claude. So no frontend's file allows a write to another frontend's state. A glob of the template, such as ~/Research/**/.git/hooks, passes through after the expansion. The template's excludedCommands is not carried: under srt the whole process is inside the sandbox, so no command can run outside it. The masked credentials of srt are not used.

The install ​

harness install renders the Claude Code settings template as it does for ~/.claude/settings.json, with the profile and the network overlay, and gives its sandbox object to srt_settings. It writes each file as JSON indented by two spaces, with the keys in the order above and a final newline. The files belong to no frontend's plan: a change of them prints no restart line. A frontend that [setup] does not choose gets no file, and with no frontend chosen the install renders no file. The install does not change what it writes to ~/.claude/settings.json. Because it renders the template with the network overlay for every chosen frontend, a broken overlay stops the install with status 2 also when claude is not chosen, for example an allow entry that is a URL.

With at least one frontend chosen, the install also copies the launcher sandbox/agentbox to ~/.local/bin/agentbox with mode 755, a directory that a session cannot write. With claude chosen it writes Claude Code's override beside the settings files:

text
~/.config/research-harness/sandbox/claude-inner-off.json   {"sandbox": {"enabled": false}}

A launcher whose mode differs from 755 is a change, as a file whose bytes differ is.

The install writes nothing through a symlink. So where ~/.local/bin is a symlink and a frontend is chosen, harness install --apply exits with status 2, writes nothing, and names the path and the symlink.

The launcher agentbox ​

agentbox is a POSIX sh script that starts one CLI frontend under srt:

sh
agentbox <frontend> [args...]

The frontends are the commands claude, opencode, omp and agy. agentbox runs

sh
~/.local/bin/srt --settings ~/.config/research-harness/sandbox/<policy name>.json -- \
    <program> <extra> <args...>

with exec, so the exit status of srt is its own. The policy name is antigravity for agy and the frontend's name otherwise. <program> is the path that command -v gives on the caller's PATH without each entry that matches */cmux-cli-shims/* or */cmux-cli-shims. In a cmux terminal the first claude on the PATH is a shim of cmux, which srt cannot read; the shim itself skips the same entries to find the real claude where the cmux wrapper is absent. A claude under agentbox therefore runs without the cmux wrapper. The filter decides only which program runs: the program gets the caller's PATH unchanged. The caller's arguments follow <extra>, each passed as one argument, unchanged. The -- ends the options of srt, which otherwise reads a --settings of the frontend as its own.

frontend<extra>why
claude--settings ~/.config/research-harness/sandbox/claude-inner-off.jsonClaude Code's own sandbox fails inside the sandbox of srt, so the override turns it off
opencode--standaloneOpenCode runs its server as its own child inside the sandbox, not in a background service that a run outside the launcher could have started
omp--approval-mode yolooh-my-pi runs its tools without a prompt; the sandbox of srt is the boundary
agynothing

The frontend gets AGENTBOX=1 and the three cache variables below in its environment; every other variable stays the caller's. agentbox runs only the srt in ~/.local/bin, never one found on the PATH. So it starts nothing before harness setup has installed srt in ~/.local/bin.

Each run makes one new directory with mktemp -d "${TMPDIR:-/tmp}/agentbox.XXXXXX", below $TMPDIR, or below /tmp where TMPDIR is unset or empty, with the subdirectories npm, uv and texmf-var. The sandbox denies the caches of these tools in the home directory, so agentbox sets and exports a cache variable for each, where the caller's variable is unset or empty:

variabletoolvalue
npm_config_cachenpm<run directory>/npm
UV_CACHE_DIRuv<run directory>/uv
TEXMFVARLaTeX, for example the font cache of lualatex<run directory>/texmf-var

A caller's non-empty value stays. An empty value counts as unset: an empty UV_CACHE_DIR stops uv, and an empty npm_config_cache sends npm to ~/.npm. The settings file of every frontend lets it write /tmp and the $TMPDIR of the install. Each run starts with empty caches, so npm and uv download again and lualatex builds its font cache again. The run directory stays after the run, because agentbox ends in exec; the system's cleaning of temporary directories removes it.

agentbox exits with status 2, starts nothing and prints one line on stderr when:

  • no frontend is named, or the name is not one of the four; the line lists the four;
  • AGENTBOX is set, so it runs inside a launcher already;
  • ~/.local/bin/srt is not an executable file; the line names harness setup;
  • the frontend's settings file, or for claude the override, is not a file; the line names the file and harness install --apply;
  • command -v finds no program of the frontend's name on the PATH without the cmux entries;
  • what command -v gives does not start with /: a shell function, for example a bash function that the caller exports and that macOS's /bin/sh imports, or, where /bin/sh is dash, a program in a relative PATH entry; the line names the program and what was found;
  • the frontend is claude and an argument is --settings or starts with --settings=: Claude Code keeps only the last --settings, so the caller's would replace the override and turn Claude Code's own sandbox on again. More settings go in the user settings instead;
  • mktemp cannot make the run directory, for example because $TMPDIR is not a directory; the line names the directory.

A refused run makes no run directory.

agentbox -h and agentbox --help print the usage and exit 0.

The pinned srt ​

harness setup installs ~/.local/bin/srt, the srt that agentbox runs, with any frontend chosen, from two files of the harness:

filewhat it holds
sandbox/srt/package.jsona private package with one dependency, @anthropic-ai/sandbox-runtime at exactly 0.0.81, and the override of node-forge to exactly 1.4.1
sandbox/srt/package-lock.jsonthe tree that npm resolves from that file: srt 0.0.81, node-forge 1.4.1, zod, commander and @pondwader/socks5-server, each with its resolved URL on registry.npmjs.org and its sha512 integrity

The srt package ships no lockfile of its own, so a pin of srt alone would leave its four dependencies to the registry on each install. npm ci installs exactly the tree of the lockfile, refuses a package whose bytes do not match its sha512, and fails on a lockfile whose dependencies do not match those of package.json; it does not compare the override with the lockfile. The override keeps node-forge at 1.4.1: srt asks for ^1.4.0, and 1.4.0 has eleven advisories that 1.4.1 fixes.

The step copies both files into a scratch directory below ~/.local/share/research-harness/, beside srt/, and runs npm ci --ignore-scripts --no-audit --no-fund there with the npm of the PATH, so no install script of a package runs. After npm exits 0 and has made node_modules/.bin/srt, the step moves the directory to ~/.local/share/research-harness/srt/0.0.81/, links ~/.local/bin/srt to ~/.local/share/research-harness/srt/0.0.81/node_modules/.bin/srt, and removes the directories of other versions and the links below srt/. A file at ~/.local/bin/srt is replaced by the link. The settings template allows no write at or above ~/.local/share/research-harness and denies writes to ~/.local/bin, so a Claude Code session can change neither the tree nor the link.

The step fails, and writes nothing below srt/ and nothing in ~/.local/bin, when npm is not on the PATH, when node --version is below 22.12.0, the engines.node of srt 0.0.81 (npm ci only warns there), when npm exits non-zero, or when ~/.local/bin/srt is a directory. For a failed npm, the line holds the cause from npm's stderr: the text of its npm error code line and its first npm error line of other text, such as code ENOTFOUND; network request to https://registry.npmjs.org/… failed. It removes its scratch directory in every case. A plan finds nothing to do, and has no such step, when srt/0.0.81/package-lock.json holds the bytes of the shipped lockfile, node_modules/.bin/srt exists, and ~/.local/bin/srt links to it; so a change of the shipped lockfile installs again. The Homebrew copy of srt, where one is installed, stays as it is.

The probe battery ​

scripts/probe-agentbox.py checks that each frontend's settings file holds the boundary that the policy means. Run it after harness setup and harness install --apply, from a plain terminal on macOS: srt refuses a sandbox inside its own, so no session and no agentbox can run it.

sh
python3.14 ~/Research/Harness/scripts/probe-agentbox.py [--out DIR] [--timeout S] [--no-model] [FRONTEND ...]
optionwhat it does
FRONTENDclaude, opencode, omp or agy; with none named, all four
--out DIRthe directory of the report; by default ~/Research/.scratch/agentbox-probes/<UTC date and time>
--timeout Sthe time limit of each frontend probe, in seconds; 300 by default
--no-modelruns no frontend probe, so the run makes no model call

The script exits with status 2, runs no probe and prints one line on stderr when SANDBOX_RUNTIME or AGENTBOX is set, on a platform other than macOS, for an argument that is not a frontend or an option, for --out or --timeout with no value, for a --timeout that is not a whole number above 0 in ASCII digits, when ~/.local/bin/srt or ~/.local/bin/agentbox is not an executable file, and when the settings file of a chosen frontend is missing. The line names the cause, and harness setup or harness install --apply where one of them installs the file.

It runs four classes of probes for each chosen frontend:

classidshow it runswhat it asks
listenerL:<port>, L:<port>/pathcurl under srtdoes each TCP listener on 127.0.0.1, on ::1 or on every interface answer 401, 403 or 407
read and writeR1–R8, W1–W14/bin/sh -c under srtcan a command read a secret, or write a hook, a launch agent, a shell start file or another frontend's state
network and processN1–N9, X1–X8/bin/sh -c under srtwhich hosts it reaches; can it open an app, send an Apple Event, mount, submit a launchd job, signal a process outside or start a sandbox of its own
frontendF1–F7the frontend under agentboxdoes it start, do its tools run inside the sandbox, does its own file tool read outside, does it reach Kaimon, and do its own gates hold

The script lists the listeners with lsof -nP -iTCP -sTCP:LISTEN, outside srt, before the other probes. It asks a listener on every interface (*:<port>) at 127.0.0.1:<port>, and each address and port once, at /. OpenCode's server takes a password, OPENCODE_SERVER_PASSWORD, and / of it can answer without one, so a listener whose command is opencode is also asked at /path, a route that OpenCode's binary names, in a row L:<port>/path. A listener answers as the policy means with 401, 403 or 407: 407 is a proxy's request for authentication, as srt's own proxies give it. A shell probe runs as ~/.local/bin/srt --settings ~/.config/research-harness/sandbox/<policy name>.json -- /bin/sh -c <probe> from ~/Research, so its boundary is the settings file alone. A frontend probe runs the frontend's non-interactive form under agentbox: claude -p, opencode run --auto, omp -p or agy --dangerously-skip-permissions -p, with the prompt as the value of -p; past --timeout it is stopped with its process group. Every probe is harmless where the sandbox fails to stop it: a read prints a count, never content; an append opens the file and writes nothing; a probe that creates a file deletes it. After each frontend's shell probes, the script removes the launchd job of X4 and unmounts the devfs of X3 where either is left. The probes use a run directory <out>/run, with a secret.txt, a .env and a git repository whose remote is this repository.

Each probe gets one verdict:

verdictmeaning
matchthe result is the expected one
MISMATCHthe result is not the expected one
absentthe file or directory that the probe names does not exist, so the probe does not run
skippedthe probe does not apply: R8 for agy, X5 with no listener on port 2828 of 127.0.0.1 or of every interface, the frontend probes with --no-model or with no program on the PATH, F6 with no plain opencode listening
timeoutthe probe ran past its limit
voidF3, which expects a word to be missing, where F1 of the same frontend is not match: a frontend that never started also lacks the word, so the result proves nothing; its detail is F1 shows no start
an observationF5 records the exit status of agy --sandbox, and F7 whether ~/.omp/agent/config.yml changed during F1–F4 of omp: unchanged, changed, or absent where the file exists neither before nor after

The expected value is the policy's intent, not what the current files do. So a MISMATCH is a finding for the policy, the settings files or the launcher, and a run of a policy with a known gap exits 1. A probe's output goes into the detail of its row on one line: whole up to 200 characters, else its first and its last 100 characters joined by …, so a failure keeps its cause and its last state. The script writes report.tsv, every row with the columns frontend, id, expected, got, verdict and detail, and report.md: the rows other than L: as a table; a section ## Listeners with one line per command, status and verdict of the L: rows, which names the number of ports, the ports in numeric order and the frontends; the count of each verdict over every row in ## Counts; and the manual steps: change the model once under agentbox omp, and, where F6 was skipped because no plain opencode listened, run it again with a plain opencode in another terminal. It prints the path of report.md last, and exits 0 when no probe is MISMATCH or timeout, and 1 otherwise; a void alone does not make it 1.
